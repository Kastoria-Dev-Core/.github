# Contributing to Kastoria Dev Core

Thanks for your interest. These guidelines apply to every repository in the organization unless a repository has its own CONTRIBUTING file.

## Getting started

1. Find an issue you want to work on, or open a new one describing your idea.
2. Comment on the issue so others know you are on it.
3. Fork the repository (or create a branch if you are an org member).
4. Make your changes in a branch with a short descriptive name, for example `fix/timetable-sorting` or `feat/dark-mode`.
5. Open a pull request that links the issue (`Closes #12`).

## Commits

- Keep commits small and focused on one change.
- Write the subject in the imperative mood, under 72 characters: `Add stop search to map screen`.
- Conventional prefixes (`feat:`, `fix:`, `docs:`, `chore:`) are welcome but not required.

## Pull requests

- Describe what changed and why. Screenshots help for UI changes.
- Make sure the project builds and existing tests pass.
- At least one maintainer review is needed before merging.
- Be patient, everyone here is a student with exams too.

## Code style

Follow the conventions already used in the repository. If the project has a formatter or linter configured, run it before pushing.

## Questions

Open a discussion or an issue, or ask on our Discord server. No question is too basic.

## Code of Conduct

By participating you agree to follow our [Code of Conduct](CODE_OF_CONDUCT.md).
